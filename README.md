# 首命中规则审计台（First-Hit Rule Audit Console）

一款**完全本地运行**的访问控制规则审计工具。规则按自上而下的顺序求值、**首条匹配即生效**；
本工具精确计算每条规则在该语义下**实际可达的流量区域**，识别被前序规则遮蔽的部分，
即使该遮蔽由**多条规则的并集共同覆盖**造成也能识别，并为每个问题给出**可复现的示例报文**与**遮蔽来源**。

- 技术栈：React 18 + TypeScript + Vite + [ipaddr.js](https://github.com/whitequark/ipaddr.js)
- 纯前端应用，无后端，所有分析都在浏览器内完成，规则数据不外传
- 规则维度：**源 IPv4 CIDR × 源端口区间 × 协议（TCP / UDP / ANY）× 动作**

```bash

```

## 功能说明

### 规则编辑与拖拽排序

- 在表格中直接编辑规则名称、CIDR、端口区间、协议、动作
- 拖拽行首的 ⠿ 手柄（或整行）即可调整顺序；顺序就是匹配优先级
- 支持新增、复制、删除、一键清空、恢复内置演示规则

### 调序影响预览（拖拽后先预览、再确认）

拖拽松手后**不会立即改动规则顺序**，而是先弹出「调序影响预览」：
工具分别用**当前顺序**与**候选顺序**执行同一份审计，并**按规则 id 对齐**两份结果。

弹窗内容：

1. **受影响规则表**：逐条列出旧/新序号、状态（旧 → 新）、有效报文空间（旧 → 新）
   及变化量（绿色 `+` 增加 / 红色 `−` 减少）。仅位置移动、审计结果不变的规则标注
   「仅序号变化」；序号未变但因其它规则上下移动而被影响的规则同样会列出。
2. **首命中动作发生变化的流量**：每一组都给出至少一个**可复现样例报文**
   （`协议 src=IP:端口`，可一键复制），并标明变更前后命中的规则序号、名称、动作，
   以及该组影响的报文空间大小。
3. **仅易主、动作不变的流量**：首命中规则改变但动作一致，单独分组列出供参考。
4. **无实际差异时明确提示**：候选顺序下状态、有效空间、每个报文的首命中结果都不变时，
   顶部给出绿色提示；仍可选择「仍要应用该顺序」或直接取消。

点击「确认应用候选顺序」后规则才一次性重排并刷新审计；
点击「取消」（或点遮罩 / 按 Esc 区域）则**保持原顺序**。
**非法规则继续按既有语义排除**：不参与首命中计算，仅在表中展示其序号变化。

### 首命中可达性审计

规则求值采用与真实 ACL 相同的语义：对任意一个报文（源 IP、源端口、协议），
**列表中第一条覆盖它的规则生效**，其后覆盖同一报文的规则对该报文永远不可达。

工具把全部规则声明的 CIDR 递归切割成互斥的 IP 原子块、把端口区间切成互斥的端口原子段，
连同协议维构成离散报文单元，逐个单元登记其“首个命中者”，从而精确得出每条规则：

| 状态 | 含义 |
| --- | --- |
| **可达** | 声明区域全部在首条命中语义下归本规则 |
| **部分遮蔽** | 一部分区域被上方规则夺走，其余仍可达；展开可见“实际可达区域” |
| **完全遮蔽** | 声明区域内的任何报文都先命中其它规则，本规则永不生效 |
| **非法** | CIDR / 端口 / 协议 / 动作校验失败，**不参与分析**（其它规则的审计不考虑它） |

- **共同覆盖识别**：当规则 R 的区域没有被任何**单条**前序规则独立完全遮蔽，
  但被前序规则的**并集**完全覆盖时（例如两条各盖一半 `/25` 的规则盖住一条 `/24`），
  R 仍被判定为完全遮蔽，并标注 **“共同覆盖”** 徽章，同时列出全部参与来源。
- **遮蔽来源**：逐条列出遮蔽了本规则的上方规则（名称、动作、贡献单元数，按贡献排序）。
- **可复现示例报文**：
  - *可达样例*：一个实际命中本规则的报文；
  - *遮蔽样例*：一个看似属于本规则、实际命中前序规则的报文，并注明命中的规则编号、名称与动作。
  - 报文形如 `TCP src=192.168.1.10:22`，可一键复制。

### 实际可达区域展示

展开部分遮蔽的规则，可以看到其有效区域按协议合并后的精确表达：

- 一组规范 CIDR（相邻原子块会自动合并回更大的 CIDR）
- 一组合并后的端口区间
- 该区域的报文空间大小（IP 数 × 端口数）

### JSON 导入

点击「粘贴 JSON 导入」，支持三种形态：

```json
[
  { "name": "允许内网 Web", "cidr": "10.0.0.0/8", "portStart": 80, "portEnd": 443,
    "protocol": "TCP", "action": "allow" }
]
```

```json
{ "rules": [ { "cidr": "0.0.0.0/0", "portStart": 0, "portEnd": 65535,
               "protocol": "ANY", "action": "deny" } ] }
```

也可以直接粘贴本工具**导出的审计报告**（`{ "entries": [...] }`）回填规则。

可选择“替换全部规则”或“追加到现有规则”。字段缺失时按空值处理；
**非法 CIDR / 端口不会导致导入失败**，该规则会保留在列表中并标记为非法、不参与分析。

### 导出审计结果

点击「导出审计结果」，得到包含统计摘要与每条规则完整审计明细的 JSON
（状态、声明/有效报文空间、可达区域、遮蔽来源、共同覆盖标记、示例报文、非法原因等），
支持复制到剪贴板或下载为 `.json` 文件。「导出规则」则只导出可再次导入的规则数组。

## 校验规则（非法项不参与分析）

- **CIDR**：必须是规范的 IPv4 CIDR —— 点分十进制四段、每段 0–255、前缀 0–32、
  主机位必须为零（`10.0.0.5/24` 会被拒绝，并提示规范写法 `10.0.0.0/24`）；
  不接受 IPv6、缩写地址（如 `10.0.0/8`）。
- **端口**：起止均为 0–65535 的整数，且起始 ≤ 结束。
- **协议**：`TCP` / `UDP` / `ANY`（大小写不敏感，导入小写 `tcp` 也可识别）。
- **动作**：非空文本（如 `allow` / `deny`，可自定义）。

非法规则以红色标出并展开列出原因；它们被排除在遮蔽分析之外，
即一条非法规则不会遮蔽后面的任何规则。

## 工作原理（简要）

1. 校验全部规则，分离合法 / 非法规则（非法规则不进入后续步骤）。
2. 以 `0.0.0.0/0` 为初始块，把每条合法规则的 CIDR 递归二分插入，
   得到一组两两互斥、按 CIDR 对齐的 **IP 原子块**；端口维同理取所有区间端点形成**端口原子段**。
3. 单元空间 = IP 原子块 × 端口原子段 × {TCP, UDP}（`ANY` 同时占据两种协议）。
4. 按规则顺序遍历，每个单元登记第一个覆盖它的规则（owner）；
   后续规则若声明了该单元，则该单元记为被遮蔽，并记录遮蔽来源。
5. 汇总每条规则的声明/有效报文空间、状态、遮蔽来源；
   将其有效单元合并成规范 CIDR 与端口区间；选取确定性的代表单元生成示例报文。

单元数量受规则中不同 CIDR / 端口边界数量约束（数十条规则量级为数百到数千单元），
因此在浏览器中可以即时完成。

**调序预览**只是把同一套审计对候选顺序再跑一遍：由于规则集合不变，IP / 端口原子
划分与顺序无关，两次结果共享同一套原子空间，因此可以逐单元比较首命中归属（按规则 id），
精确得到归属转移、动作变化分组及确定性的可复现样例。

